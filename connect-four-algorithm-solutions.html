1. Threat-Aware Alpha-Beta with a Learned Evaluator

Credits: Keming Sun

Problem. Choose a legal column in Connect Four when a fixed search budget prevents exploring every continuation.

Key idea. Keep alpha-beta as the search engine, then improve both parts that determine its practical strength: use tactical knowledge to search urgent moves first, and use a fitted evaluator to score positions at the search horizon. Iterative deepening and a transposition table make the limited budget go further.

How it works

The search uses negamax with Principal Variation Search (PVS). It searches the current best line with a full window. Later moves first get a cheap, narrow-window probe; only a move that appears to beat the current best earns a full re-search. Tactical ordering places immediate wins and forced blocks first, then uses the transposition-table move, killer moves, history scores, and center preference. Moves that gift the opponent a playable win are delayed.

At a leaf, terminal outcomes take priority. A nonterminal board is scored by a small neural evaluator whose inputs combine board occupancy with hand-designed threat features, including gravity-aware winning squares and parity. The evaluator helps compare quiet positions; the rule-based layer handles urgent tactical facts.

Why it works

At a fixed depth, PVS preserves alpha-beta's minimax result because any move that might improve the current bound is re-searched accurately. Better ordering makes more probes fail low, so the search can prune more work. The learned evaluator improves the estimate when the search reaches a nonterminal horizon.

Complexity

With branching factor b (at most 7) and depth d, worst-case time remains O(bd); excellent ordering can bring alpha-beta near O(bd/2). The transposition table uses space proportional to the number of stored positions.

2. Tactical, Value-Guided Monte Carlo Tree Search

Credits: Qingyang Li

Problem. Find a strong move by spending a fixed successor budget on the most informative parts of the game tree, while recognizing tactical results that can be proved exactly.

Key idea. Run real MCTS iterations, not just a tactical scan. A gravity-aware tactical pass ranks candidate moves and supplies priors; a learned value estimates newly reached positions. The tree search repeatedly selects, expands, evaluates, and backs up results. Solved wins and losses propagate through the tree and can override statistical estimates.

How it works

At each node, the agent selects an unresolved edge using a UCT-style score that combines the edge's observed result, an exploration bonus, and a prior bias from tactical move ranking. It expands a child, evaluates the new position with the learned model, then backs up both the value estimate and any solved outcome. The selection score balances trying promising moves with exploring less-visited ones.

When all children needed to establish a result have been resolved, the node can become proven: one winning child proves a win, while a fully examined set of losing children can prove a loss. The agent skips solved-losing edges. Search continues until the root is solved or the 2,000-child-generation budget is reached; then it returns a proven win when available, otherwise the best remaining edge by its search statistics.

Why it works

Unlike fixed-depth alpha-beta, MCTS allocates more work to branches that look promising or remain uncertain. The learned value avoids relying on random playouts, while tactical priors and proof propagation give the tree useful structure before many visits accumulate. Statistical confidence and exact proof remain separate: a high estimated value is not itself a solved result.

Complexity

The search permits at most 2,000 successor generations. Each expansion also requires feature analysis and usually a model evaluation; selection and backup work are proportional to the traversed path. Memory is proportional to the nodes and edges retained in the tree. The actual number of iterations can be lower when the root is proved early.

3. Proof-First Endgame Search with an Alpha-Beta Fallback

Credits: Zichun Zhao

Problem. In a late-game position, determine whether the current player can force a win, draw, or loss. If an exact answer is too expensive, still return a strong move.

Key idea. Spend a bounded first pass trying to prove the game-theoretic outcome. Use three-valued results—proven, refuted, and unknown—so budget exhaustion never masquerades as evidence. When proof does not finish, continue with iterative-deepening alpha-beta and a gravity-aware hand-written evaluator.

How it works

With 18 or fewer empty cells, a dedicated win/draw/loss search gets a separate cap of 800 generated children. It first asks whether the current player can force a win; if not, a second threshold query distinguishes a draw from a forced loss. A completed proof returns an exact result. An interrupted proof returns unknown, and the agent resumes ordinary search using the budget and generated children that remain.

The fallback scans four-cell windows to find immediate winning squares, safe moves, and development potential. It prefers a forced win, filters moves that hand the opponent an immediate win, and ranks the rest by tactical value and center control. At the depth limit, it avoids evaluating in the middle of a forced blocking sequence.

Why it works

A completed WDL proof is exact because it accounts for the required alternatives at both players' turns. The three-valued result preserves soundness under a hard budget: only exhaustive evidence proves or refutes a claim. The heuristic search handles positions where the proof is inconclusive.

Complexity

A proof search is exponential in the worst case, O(bd), but its explicit node cap bounds the work spent in that phase. The fallback also has worst-case O(bh) time at search depth h; alpha-beta pruning, threat ordering, and cached features reduce practical work.
